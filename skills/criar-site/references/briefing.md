# Briefing

Copie este modelo para o início do `PLANO.md` e preencha. O que não foi dito fica como pergunta, não como suposição.

```markdown
## Briefing

- **Projeto:** nome e frase de uma linha sobre o que é.
- **Objetivo da página:** a única ação que mais importa (ex.: agendar demonstração).
- **Público:** quem chega, de onde vem, o que já sabe.
- **Tipo:** landing | dashboard | app.
- **Tom:** três adjetivos.
- **Conteúdo disponível:** textos, números, depoimentos, logos, preços (diga o que é real e o que é marcador).
- **Seções desejadas:** lista na ordem em que devem aparecer.
- **Restrições:** idioma (PT-BR por padrão), prazos, itens proibidos, integrações (formulário, vídeo, mapa).
- **Referência:** pasta do design system primário (e do secundário, se houver).
```

Perguntas úteis, se faltarem respostas:

1. Qual é a ação principal que a pessoa visitante deve fazer?
2. Que números ou provas existem (clientes, resultados, prêmios)?
3. Há conteúdo que precisa ser marcado como provisório?
4. O formulário vai enviar para algum lugar? A skill gera front-end estático: sem destino, o formulário fica marcado como placeholder.
